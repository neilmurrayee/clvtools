# Audit: paper and R package against this implementation

Date: 2026-08-31. Compared against CLVTools 0.12.1 (`.Rlib/`) and the paper's
LaTeX source (`arXiv-2602.09845v1/jss5634.tex`).

**Status: all fourteen done**, 2026-08-31. Each is marked ☑ below with what it
turned into. Fixtures for the interface layer are generated by
`tools/oracle/generate_interface_fixtures.R`; the prediction fixtures for the
time-varying model by `tools/oracle/generate_dyncov_fixtures.R`.

The suite went from 622 tests to 808 (24 `paper`, 221 `oracle`, 114 `slow`),
still at 100% line coverage of `src/`. Four things surfaced that were not in the
original list and are recorded in the README's findings: the paper's §6.4.2
table is not reproducible from CLVTools 0.12.1's own fit; CLVTools predicts from
a correlated fit with the *uncorrelated* expressions; this package's covariate
standard errors were misaligned under an equality constraint; and its Hessian
step was small enough to lose four digits to cancellation.

**Method.** Three passes. (1) Every code chunk in the paper — 34 of them —
matched to a Python call. (2) The paper's functionality tables: Table 2
(the `clvdata` / `latentAttrition` / `predict` / generics interface), Table 3
(descriptive plots), Table 4 (model families and their options). (3) Every
symbol in CLVTools' `NAMESPACE` — 11 exports, 11 exported S4 generics, 39 S3
methods — checked for a counterpart here.

**Summary.** The estimation core is complete: all three latent attrition
families, the spending model, time-invariant and time-varying covariates,
correlation, constraints, regularization, prediction for the Pareto/NBD, the two
model diagnostics, bootstrap intervals, and the calendar time units. What is
missing is mostly the *surrounding interface* — the descriptive layer of §6.1.2,
the inference generics, and three places where the paper prints output this
package cannot yet produce.

Verified as **not** a gap while auditing: CLVTools predicts from a *correlated*
Pareto/NBD using the plain uncorrelated `PAlive` and `CET` expressions — the
correlation enters prediction only through the parameter estimates. Checked in R
at the fitted parameters, difference exactly 0. `PnbdCorrelatedParams.as_dict()`
already does this; task 13 pins it.

## P1 — paper output this package cannot reproduce

### ☑ 1. `summary()` for transaction data — §6.1.2

The paper prints a 39-cell table (customers, transactions, zero repeaters,
mean spending and interpurchase time, each with SD, split three ways across
estimation / holdout / total). `ClvData.__repr__` prints five of them.

*Done when:* `ClvData.summary()` returns that table as a frame, a `-m paper`
test reproduces every printed cell, and the "3,183 purchases against 3,187 rows"
same-day aggregation is asserted rather than incidental.

**Done:** `ClvData.summary()`, with `mean_interpurchase_times()` behind it.
Every printed cell reproduced (`-m paper`), and the full-precision values
checked against a recomputation the generator asserts against `summary()`
itself.

### ☑ 2. Prediction with time-varying covariates — §6.4.2

No `predict()` path for `PnbdDynCovParams`, and `data/apparelDynCovFuture.csv`
is exported but has no loader. The paper extends the covariate series into the
prediction window (`rbind(apparelDynCov, apparelDynCovFuture)`), predicts 95
weeks at a 7.5% rate, and prints three rows.

*Done when:* `load_apparel_dyn_cov_future()` exists; `predict()` accepts dyncov
parameters and future covariate data; an oracle fixture of CLVTools' own dyncov
prediction table is committed; the paper's three rows are a `-m paper` test.
Expect this to need `-m dyncov_fit` for the fit, with the prediction itself
tested at CLVTools' published parameters so it stays in the fast suite.

**Done:** `clvtools.pnbd.dyncov_predict` — the ABCD table, CET and DECT — plus
`load_apparel_dyn_cov_future()` and a `predict()` path. The paper's scenario
reproduces CLVTools 0.12.1 to 1e-12; the ABCD table matches row for row.

### ☑ 3. Likelihood ratio test — §6.5.3

`lrtest()` is used to compare the constrained and unconstrained dyncov fits, and
prints `#Df 9/10`, `LogLik -11776/-11763`, `Chisq 26.072`, `Pr(>Chisq) 3.289e-07`.
Nothing here computes it.

*Done when:* a `likelihood_ratio_test(restricted, unrestricted)` returns df,
statistic and p-value; tested on the cheap static-covariate nested pair against
an R fixture, and on the paper's dyncov pair under `-m dyncov_fit`.

**Done:** `clvtools.inference.likelihood_ratio_test`, checked against
`lmtest::lrtest` on the static-covariate nested pair (χ² = 10.943).

### ☑ 4. The descriptive plots of §6.1.2 (Table 3)

Five descriptive plots exist for a data object; this package has none of them —
`diagnostics` covers only the two *model* diagnostics and the spending density.
Their `plot=FALSE` frames, confirmed in R today:

| `which` | Frame | Status |
|---|---|---|
| `"tracking"` | `period.until, variable, value` | model-only here; `tracking_data` requires an `expectation` |
| `"frequency"` | `num.transactions, num.customers` | missing |
| `"interpurchasetime"` | `Id, mean.interpurchase.time` | missing |
| `"timings"` | `Id, type, variable, value` | missing |
| `"spending"` | `Id, Spending` | missing (the §6.2.4 model density is a different plot) |

*Done when:* each returns the same frame as CLVTools' `plot(..., plot = FALSE)`,
row for row, against a committed fixture; `sample=` ("estimation" / "holdout" /
"full") is honoured where CLVTools honours it; `tracking_data` accepts
`expectation=None` for the model-free version.

**Done:** `frequency_data`, `interpurchase_time_data`, `spending_data`,
`timings_data` in `clvtools.diagnostics`, and
`tracking_data(expectation=None)`. Each matches `plot(..., plot = FALSE)` row
for row.

### ☑ 5. `predict()` for the BG/NBD and GGom/NBD

`predict()` is Pareto/NBD-only. Both other families have `probability_alive` and
`conditional_expected_transactions` but no way into the prediction table.
Confirmed in R today: for these two families CLVTools returns
`period.*, actual.x, actual.period.spending, predicted.mean.spending,
predicted.period.spending, CET, PAlive` — **no `DERT` and no `predicted.CLV`**,
so the scope is narrower than the Pareto/NBD's.

*Done when:* `predict()` dispatches on the parameter type, omits the DERT
columns for these families, and both tables match an oracle fixture.

**Done:** `predict()` dispatches on the parameter type and omits
`DERT`/`predicted.CLV` for these two, as CLVTools does. Covariate prediction
for both families is covered too.

### ☑ 6. Prospective customers as an API — §6.3.4

The two scalars are reproduced (2.218635, 39.1372) but only as calls to
`expectation()` and `expected_mean_spending()`. There is no `newcustomer()` /
`newcustomer_spending()`, and none of the covariate-aware
`newcustomer.static()` / `newcustomer.dynamic()` the section points at for
scenario comparison ("region A versus region B").

*Done when:* the three constructors exist, `predict()` accepts them in place of
data, and the covariate variants are checked against an R fixture at given
covariate values.

**Done:** `newcustomer()`, `newcustomer_static()`, `newcustomer_dynamic()` and

## P2 — interface parity where the numbers already exist

### ☑ 7. `vcov()`, `confint()`, and `summary()` for every fit

`standard_errors()` exists on the Pareto/NBD and its two covariate variants;
`summary()` (the coefficient table with z- and p-values) exists **only** on
`PnbdStaticCovParams`. The Gamma-Gamma, BG/NBD, GGom/NBD, correlated and dyncov
fits have none, though all carry a Hessian. Table 2 lists `vcov()` and
`confint()` as available for all fitted models; neither exists anywhere here.

*Done when:* all five live on a shared mixin, checked against `vcov()` and
`confint()` fixtures for each family. Note CLVTools' `confint` returns a plain
Wald interval that can run negative (`beta` lower bound −22.9 at the paper's
fit) — reproduce that rather than clipping it.

**Done:** The `clvtools.inference.Fitted` mixin. Fixing the constrained Hessian
was a bug fix, not just a port — see the README's findings.

### ☑ 8. `fitted()`

Returns `period.until, period.num, expectation` in R. Missing here; the pieces
exist inside `tracking_data`.

**Done:** `clvtools.diagnostics.fitted_data`.

### ☑ 9. Data-object accessors: `subset()`, `as.data.frame(sample=, ids=)`, `nobs()`

§6.1.2 demonstrates all three (`sample = "full" | "estimation" | "holdout"`,
`ids = "1"`, `subset(clv.apparel, Price >= 50 & Price <= 100)`). `ClvData`
exposes `.transactions` and the two summaries, with no sample slicing.

**Done:** `as_data_frame(sample=, ids=)`, `nobs()`, `holdout_start`; `subset()`
is `as_data_frame().query()`, with the oracle's row counts pinned.

### ☑ 10. A `latent_attrition()` / `spending()` facade

Every code chunk in the paper's walkthrough goes through these two entry points
with a `family` and a `formula` (`~ Gender + Channel | Gender + Channel`, and
`~ . | .` with `names.cov.constr`). Here the caller picks `fit_pnbd` vs
`fit_pnbd_staticcov` vs `fit_bgnbd_staticcov` and passes covariate names
positionally. A thin dispatcher over the existing fits would make
`docs/paper.md` read like the paper.

*Done when:* `latent_attrition(family, data, formula=None, ...)` and
`spending(family, data, remove_first_transaction=True)` cover every chunk in
§6.2–§6.5, and `docs/paper.md` uses them.

**Done:** `clvtools.estimate`, with S6.4's formula parsed by `parse_formula`.
`docs/paper.md` now estimates through them, as the paper does.

and `tests/test_families.py` cite the model-family table as Table 3.
In the published PDF, Table 3 is the descriptive-plot table and Table 4 is the
models overview (`pdftotext` on `2602.09845v1.pdf`, captions on p. 1077 and
1339 of the extracted text). Mechanical rename.

**Done:** Twenty references corrected across the README, docs, source and
tests.

### ☑ 13. Appendix B run-time comparison

**Done:** `tools/benchmark.py`, simulating from Appendix B's base parameters.

### ☑ 14. Pin the correlated-prediction finding

## Not gaps

- `bgbb` is exported by CLVTools but is absent from the paper (Table 4 lists
  three families). Out of scope unless the scope changes.
- `optimx.args` — covered by `method=` plus the `overrides` escape hatch in
  `clvtools._optimize.options_for`.
- `remove.first.transaction=FALSE` — `ClvData.spending_summary` takes it.
- `plot(..., other.models=, label=)` (Figure 12) — `tracking_data` takes a
  `model_name`, so several frames can be concatenated; only a convenience
  wrapper is missing, folded into task 4.
